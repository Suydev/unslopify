# Reference library

Taste comes from comparing good work, not from memorising rules. This file is a diverse, sourced starting pack: where to look, which specific sites to study, and what to take from each. It exists so a rewrite never falls back on the first three templates an agent happens to recall.

**Rule:** references teach principles — scale, spacing, restraint, rhythm, hierarchy, interaction. Never copy a brand's illustrations, photography, copy, or pixel-for-pixel layout. Use 3–6 references total, at least three different families (whole site, section/component, flow or teardown), and write down what you take from each before building.

## How to use references

Write four lines before looking at anything pretty:

```text
Audience: who lands here
One job: the single action we want
Core claim: what changes for them, in one sentence
Proof: the strongest evidence we have
```

If **Proof** is blank, get proof first; no reference will save the page. Then pick references by section, not by copying one site: hero, features, pricing, proof, components, and one industry-matched whole site. A flow reference (what users do) and a design reference (how the interface presents it) may be different products — say which decision each one informs.

## Award teardowns: concept-first work

From Rick Creates' Site of the Day teardowns, which measure performance and assets in a real browser. These show how a concept can dictate the medium:

- **Sleep Well Creative** — a sleep guide as a scroll-read 3D picture book; chapters make the points and scenes act them out.
- **Heron AI** — an invisible product (code-checking assistant) shown as an architectural drawing the visitor checks themselves: drag a box around a fault, get the rule it breaks.
- **Jesper Landberg** — a short-content portfolio whose entire page is a bendable material; eight projects form one curved ribbon.
- **Maxima Therapy** — "see life from a different angle" becomes a slight tilt on cards, photos and menu, plus a large wheel that moves through life stages.
- **Lidar Drone Scanning** — a fictional product presented like a real one, ending in a 3D terrain map whose markers open inspection reports.
- **Gil Huybrecht** — availability, services and awards on the first screen; 19 projects on one canvas so images fly into the open case.

The transferable move: **state the concept in one sentence, then let that sentence choose the interaction**. If you cannot state it, you are adding effects.

## Four-part compatibility test

Before adopting a component from any registry, check (21st.dev's compatibility guide, 2026):

1. **Does it read your tokens?** Look for `--background`, `--foreground`, `--primary`, `--muted`, `--border`, `--ring`. Hardcoded `bg-zinc-900` means it will break on theme change.
2. **Does it install through `npx shadcn add <url>`?** Registry install means dependencies resolve and files land where your config says. Documentation-page copy-paste does not.
3. **Does it use the same primitives?** A second focus trap or portal implementation in one flow is a bug factory.
4. **Does it assume a Tailwind version?** v4 moved configuration into CSS; v3 components need translation.

After install: read the diff (two registries can both write `button.tsx`), normalise tokens in the first commit, and re-run the slop audit. A packaged system like MUI or Mantine is fine when it owns a separate product surface; mixing it inside one flow without an adapter gives you two spacing scales and two ideas of a Button.

## Reference workflow

1. Write the four-line brief (audience, job, claim, proof).
2. Choose 3–6 references across different families and name what you take from each: `01-hero-linear.png → type scale, product shot bleeding off-edge`.
3. Screenshot the live pages at desktop and mobile yourself; do not rely on a thumbnail.
4. Extract a short style spec: type, scale, colours, spacing, radius, imagery, motion, and an explicit "avoid" line.
5. Write the real copy before designing around it.
6. Build, screenshot, put it next to the references, and critique. Fix only the top three issues, re-screenshot, repeat 3–5 times.
7. Pre-launch: 10-second test with real people (what is it / who is it for / what next), performance ≥ 90 and accessibility ≥ 95, real-phone check, metadata and CTA event verified.

The 10-second test comes first. If a visitor cannot answer those three questions after ten seconds, no amount of reference polish matters.
